# GM3323D 灯光指令（v0.1.1）

2026-10-25 在本机无线 GM3323D 上验证。此文取代历史 `protocol.md` 中的灯光读改写方案；不将单机结论推广为所有固件的保证。

## 接口与长度

匹配产品名 GM3323D、VID/PID `1D57:FA60`、UsagePage `000B` / Usage 0 / 最大 Feature 132。用可共享读写句柄调用 Windows `HidD_SetFeature`，传入 **13 字节**，首字节为报告 ID `05`。不加 `04` 前缀，不补成 132 字节，不需要先读配置。

## 报文

本机已接受且用户确认青色常亮：

```text
05 0D 01 01 04 08 46 D3 FF 06 01 00 00
```

| 偏移 | 含义 | 当前程序 |
|---|---|---|
| 0 | 报告 ID | 05 |
| 1 | 指令长度 | 0D（13） |
| 2 | 配置槽 | 01 |
| 3 | 灯效 | 00 关闭，01–08 对应界面模式 |
| 4 | 效果时间参数 | 固定 04；原厂从速度档位作 9−档位编码 |
| 5 | 亮度 | 01–08 |
| 6–8 | RGB | 所选颜色 |
| 9 | 呼吸时间参数 | 固定 06 |
| 10 | 原厂固定字段 | 01 |
| 11–12 | 保留字段 | 00 00 |

原厂程序的灯光发送路径使用长度 0D 并初始化保留字节为零；协议由本机原厂程序调用参数核对和实机测试确认。本仓库独立实现协议，不分发原厂 DLL 或程序代码。当前只验证青色常亮的实际效果，其他模式完整矩阵待测试。

## 旧实现为何失败

`GetFeature(04, 132)` 实测返回含设备字符串及连续机器码的块，后续读取继续变化，不能作为当前灯光配置。首版错误地将 `05 0D` 当作可读配置签名，导致始终未进入发送。上游的完整模板回写和“ID 前缀”选项也不再用于 WPF 应用。保留的 `src/main.cpp` 与旧协议文档仅为上游历史实现。

实际灯光通过用户目视确认。Windows 返回成功只代表接口接受发送，不应冒充硬件回读校验。
